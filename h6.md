## h6 Onkohan tämä turvallinen käyttää? (Lari)


# Johdanto
Tehtävänä on tutkia TP-Link Tapo C200v3, firmware 1.4.2 valvontakameran ohjelmiston turvallisuutta.
Tavoitteena on:
* Purkaa firmware-kuva
* analysoida dump-tiedosto
* tutkia rootfs-sisältö
* etsiä haavoittuvuuksia
* mahdollisesti selvittää root-salasana
* Arvioida löydöksiä


# Firmware ja työkalut
* Aloitin tehtävän asentamalla tp-link-decrypt työkalun githubista.

* Käytin komentoa git clone https://github.com/robbins/tp-link-decrypt.

* Latasin myös moodlesta kameran dump filen virtuaalikoneeseeni.

# Firmware-kuvan purku

* Tämän jälkeen siirryin lataamaani tp-link-decrypt kansioon ja ajoin kaksi komentoa:
  * ./preinstall.sh asentaa riippuvuudet.
  * ./extract_keys.sh lataa TP-linkin GPL-julkaisut ja poimii RSA/DES-avaimet.
  * Viimeiseksi ajoin komennon "make" jonka olisi pitänyt kääntää bin/tp-link-decryptin.
 
* Make komennon ajo kuitenkin epäonnistui.

* Seuraavaksi käytin binwalkkia dump tiedoston tarkasteluun.

![image](https://github.com/mikael7943/Sovellusten-hakkerointi/blob/cdb0957ec688bf6421ac33fe8afee5e881668fc8/kuvia/N%C3%A4ytt%C3%B6kuva%202026-09-15%20105712.png)

* Mitä tästä voisi sitten päätellä?
  - Kernel löytyi Uimage-otsikon kohdassa 0x80200. MIPS Linux 3.10.14
  - Squashfs löytyi kohdassa 0x440000, tästä unohdin ottaa kuvankaapauksen, mutta se löytyi tulosteen alareunasta "zx compressed data"-osumien alapuolelta"
  - Alue kernelin ja squashfsin välissä on täynnä "xz compressed data"-osumia.
 
* Binwalkin perusteella voimme etsiä AES-avaimen.

* AES-avain on heksadesiaamlimuotoinen 128-bitin salausavain, jota käytetään AES-salausalgortimin purkuun tai salaukseen.

* AES-avainta tässä kontekstissa voidaan esimerkiksi käyttää konfiguraatiotieostojen salaukseen.

* Kokeilin vielä binwalkkia uudestaan komennolla
  - ```binwalk -e --dd='.*' dump-tapo-c200v3-1.4.2.bin```

* Binwalkin avulla pystyin purkamaan squashfs-tiedostojärjestelmän

![image](https://github.com/mikael7943/Sovellusten-hakkerointi/blob/d855d4a735e127c145a3008f661475ef43229845/kuvia/N%C3%A4ytt%C3%B6kuva%202026-09-15%20112830.png)

* Binwalk loi extracted hakemiston, joka sisältää puretun tiedostojärjestelmän.

* Extract-hakemistosta löyti hakemisto nimeltä squashfs-root, joka näyttää tältä.

![image](https://github.com/mikael7943/Sovellusten-hakkerointi/blob/b5dc88de2e34a85804c56cf21d3f8ededbae1391/kuvia/N%C3%A4ytt%C3%B6kuva%202026-09-15%20113909.png)

* Menin tarkastelemaan hakemistoa löytyisikö sieltä salasanoja tai jotain muuta hyödyllistä. En kuitenkaan löytänyt mitään

* Aloin purkamaan eriteltyä kernel-dataa. Binwalk oli puolestani luonut tiedostoja, joita pystyin stringsin avulla tarkastelemaan.

* Käytin komentoa
file 80240 ja 
strings 80240 | grep -i "TP_LINK"
 
* Tämän avulla löysin AES-avaimen.

![image](https://github.com/mikael7943/Sovellusten-hakkerointi/blob/03d8abd01a9cb5e8258d0020ebf22fc165522286/kuvia/N%C3%A4ytt%C3%B6kuva%202026-09-15%20114900.png)

* Seuraavaksi lähdin etsimään rootfsin oikeaa offsettia alkuperäisestä dumpista.

* Ajoin tällaisen komennon

for offset in 0x1B0000 0x1C0000 0x1D0000 0x1E0000 0x1F0000 0x200000 0x1BD000 0x1C6A12; do
  echo "=== offset $offset ==="
  dd if=dump-tapo-c200v3-1.4.2.bin bs=1 skip=$((offset)) count=512 status=none | \
    openssl enc -aes-128-cfb1 -d -nosalt -nopad \
    -K 54505f4c494e4b383869363637676e74 \
    -iv 55aadeadc0de4c494e5558457854aa55 | hexdump -C | head -1
done

* Komento purkaa TP-linkin firmware-dumpista löytyvää AES-salattua dataa eri offset kohdista.

* Komento rajaa eri offset-arvot firmware-binääristä ja ottaa jokaisesta offsetista 512 tavua

* Komennon avulla toivon löytäväni rivin, jossa ensimmäiset neljä tavua ovat 68 73 71 73 ja oikealla puolella teksti hsqs.

* 68 73 71 73 = hsqs = SquashFS magic bytes. Rootfs alkaa siis kohdasta 0x1C0000 alkuperäisessä dump tiedostossa.

# Root-salasanan analyysi
![image](https://github.com/mikael7943/Sovellusten-hakkerointi/blob/632bfde91b87b26e74cb227fa6639b07add6a0d9/kuvia/N%C3%A4ytt%C3%B6kuva%202026-09-15%20141315.png)

* Root salasanahash löytyi /etc/passwd:stä MD5crypt-muodossa. Miksi tämä on sitten ongelma?

* Kaikki käyttäjät voivat lukea /etc/passwd:n, mutta vain root käyttäjä voi lukea shadow-tiedoston.

* Tämä on suuri tietoturvariski, sillä hyökkääjä voi yrittää murtaa salasanan esim. offline-murto hyökkäyksellä.

* Alempana itse kokeilen saada salasanan selville johnia hyödyntäen.

* Asensin john the ripper nimisen paketin, jonka avulla kokeilin saada root salasanan selville

* Pakein saa asennettua komennolla sudo apt install john

* Loin myös valmiiksi root_hash.txt:n, jota käytän apuna salasanan murtamisessa. Tekstitiedosto sisältää aikaisemmin löytämäni root salasanahash:n.

* Törmäsin kuitenkin ongelmaan en ole varma onko tämä yleinen vai pelkästään oman debian-versioni kanssa.

* Komennolla 'john --format=md5crypt root_hash.txt' bash valitti, että john nimistä komentoa ei löydy.

* Pienen etsimisen jälkeen löysin ratkaisun ja johnia pitää kutsua eri tavalla jostain syystä.

<img width="1142" height="226" alt="image" src="https://github.com/user-attachments/assets/21f162d6-95e2-4b11-906c-6f8d0914c178" />

* Ajon jälkeen, kun mitään ei löytynyt kokeilin viel käyttää apuna rockyou.txt:tä

* Sen sain ladattua githubista komennolla ```get https://github.com/brannondorsey/naive-hashcat/releases/download/data/rockyou.txt -O ~/rockyou.txt```

* Rockyou.txt on yksi maailman tunnetuimmista salasanalistoista. Lista sisältää oikeita vuotaneita salasanoja.

# Haavoittuvuudet ja hyödyntäminen
* Kovakoodattu AES-avain mahdollistaa konfiguraation purkamisen
* Root-hash passwd-tiedostossa mahdollistaa offline-murron
* Debug-binäärejä rootfs:ssä
* Vanhentuneita kirjastoja

# Johtopäätökset

Tapo C200v3 sisältää useita haavoittuvuuksia

* Root-hash on julkisesti luettavissa
* AES-avain on kovakoodattu
* Konfiguraatiot ovat helposti purettavissa
* Debug-binäärit mahdollistavat privilege escalatoinin

Nämä haavoittuvuudet voivat johtaa laitteen kaappaamiseen ja käyttäjän yksityisyyden vaarantumiseen.
